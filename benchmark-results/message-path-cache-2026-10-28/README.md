# 消息路径缓存实施后的本地烟测

日期：2026-10-28；代码：`fd6d48a`，加上后续测试补充。原始数据见 [smoke-200x30.json](smoke-200x30.json)。

## 条件与结果

从已迁移和已种子的 `livepulse_benchmark_template_20261027` 克隆独立数据库，在同一台本地机器运行一实例 API、PostgreSQL 18.6、Redis 8.10.2 和负载生成器。使用单个直播间、200 个连接和不同用户，每秒发送 200 条，持续 30 秒；每个连接先发一条预热消息。接收验证覆盖每个预期连接与消息组合。

| 指标 | 结果 |
| --- | ---: |
| 发送 / 接受 / 失败 | 6,000 / 6,000 / 0 |
| 预期 / 收到投递 | 1,200,000 / 1,200,000 |
| 缺失 / 重复 / 错房间投递 | 0 / 0 / 0 |
| ACK p95 / p99 | 24.20 / 79.71 ms |
| 接收延迟 p95 / p99 | 24 / 78 ms |
| 调度延迟 p99 / 最大 | 7.20 / 38.23 ms |
| PostgreSQL 消息记录数 | 6,200，含 200 条预热消息 |

进程累计缓存计数包括连接建立、加入房间和预热：session 命中 6,147 次、`getSession` 调用 453 次；room 命中 6,196 次、回源 204 次；mute 命中 5,800 次、未命中 400 次。剔除 200 次连接认证、200 次加入房间检查和 200 次 mute 预热后，测量期记录了 253 次 `getSession` 重校验、约 4 次 room 回源和约 200 次 mute 回源。按 `getSession` 每次两条 SELECT、其余每次一条估算，约为 **710 条 SELECT / 6,000 次发送，即 0.118 条/次**。这是从应用计数推导的估算值，并非 PostgreSQL 的实际语句统计。

## 限制与下一步

本次未启用 `pg_stat_statements`：本地 PostgreSQL 的 `shared_preload_libraries` 为空，直接读取该视图会报错。因此无法按原基准的同一统计口径给出精确 SELECT 数。30 秒烟测也不能与[缓存前的三次五分钟 MST](../local-mst-postgres-2026-10-27/README.md)直接比较，更不能据此宣布新的持续吞吐上限。

若要确认目标 `<0.30 SELECT/发送尝试` 和新的 MST，应在隔离环境启用 `pg_stat_statements`，使用同样的预热、接收验证与调度有效性条件，至少重复三次五分钟运行，同时报告缓存命中率、ACK 和接收延迟及每个十秒窗口。
